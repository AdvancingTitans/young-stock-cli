# Vibe Integration Charter

本文记录 young 与 Vibe-Research 对接时不可随意改变的目标、边界和合规约束。后续阶段若要改变这里的任一项，应先更新本文件并说明原因。

## 项目定位

- young 保持轻量 CLI 和个人投资研究驾驶舱定位。
- 默认路径尽量保持 HTTP-only。
- 重型依赖必须是可选项，且缺失时给出清晰降级或不可用说明。
- 确定性报告默认不调用模型。
- 只有显式 `--llm` 才调用模型。

## 研究框架

- 保留 young 的 M1-M7 表达纪律。
- 不用 Vibe 的分析框架替换 young 的 M1-M7。
- M1-M6 继续以公开市场数据、确认条件、风险触发器和下一步观察点为核心。
- M7 只用于机构化综合判断，不替代前六个模块。
- 不引入主观综合评分。

## Lens 与委员会

- 单 Lens 保留单专家视角。
- `--lens all` 输出委员会最终共识、分歧、风险和组合意见，不展示逐轮辩论过程。
- Lens 只约束投资视角和表达结构，不允许覆盖证据事实。

## 数据与证据

- 缺失值不得伪装成零。
- 所有结论必须可以追踪到证据、来源和日期。
- 短线情绪是证据，不直接生成买卖信号。
- 资讯必须先去重和聚合再进入模型。

## 产品边界

- 不连接券商。
- 不自动交易。
- 不把 Vibe 的 React/FastAPI 整体并入 young。
- 不整目录复制参考仓库。
- 使用 Adapter 接入能力，保持 young 现有 CLI 体验和本地文件布局。
